# No mandatory cost operating guardrails

PanganLens is designed so the portfolio deployment does not require a paid hosting plan or a continuously running application server.

## Website

The public website is static HTML, CSS, JavaScript, and a generated JSON snapshot. It is intended for a public GitHub repository using GitHub Pages. The browser never connects to BigQuery and never receives Google Cloud credentials.

## BigQuery

BigQuery is still a metered cloud service. PanganLens therefore treats zero-cost operation as a usage target with explicit limits, not as a promise that Google Cloud can never generate a charge.

For the portfolio-sized dataset:

- Keep total BigQuery storage below the current free-tier allowance.
- Use on-demand query pricing only. Do not create slot reservations or BI Engine reservations.
- Keep dashboard snapshot refresh manual until production WIF and mapping gates are complete.
- The website snapshot exporter sets `maximum_bytes_billed` for every query and reads curated mart views only.
- The public browser never runs BigQuery queries, so visitor traffic does not multiply warehouse query cost.
- Prefer one controlled snapshot refresh after a successful pipeline publish instead of querying BigQuery on every page view.
- Review Google Cloud billing and usage before enabling any recurring production schedule.

If free-tier usage would be exceeded, the correct action for this portfolio deployment is to stop or reduce refresh frequency rather than silently accept a charge.

## Automated storage safety gate

Production readiness measures current storage across all five PanganLens datasets before operational readiness queries run.

The guard reads each dataset's storage billing model and uses the matching BigQuery storage measurement:

- logical billing uses `total_logical_bytes`;
- physical billing uses `total_physical_bytes + fail_safe_physical_bytes`.

The default safety threshold is 8 GiB while the current BigQuery free-tier storage allowance is 10 GiB. The two-GiB margin is intentional. Readiness becomes `BLOCKED` before the published free-tier ceiling is fully consumed.

This is an early warning, not a billing calculator. BigQuery storage billing reflects bytes stored over time, while `INFORMATION_SCHEMA.TABLE_STORAGE` is a current snapshot. Cloud Billing remains the source of truth for actual charges.

The storage metadata query is also subject to the readiness query ceiling. If the billing model cannot be understood, metadata cannot be read, or the storage measurement cannot be produced safely, readiness fails closed.

## Automated dashboard query dry-run gate

After storage passes, readiness dry-runs the same three curated queries used by the public website snapshot exporter:

- publish state;
- latest national commodity prices;
- province price comparison.

The dry run uses `dry_run=True` and `use_query_cache=False`, so BigQuery validates each query and returns an estimate of `total_bytes_processed` without running the data read. Each snapshot query currently has a 250 MB safety limit, aligned with the exporter's `maximum_bytes_billed` ceiling.

If any one of the three dry-run estimates is above 250 MB, if BigQuery returns no estimate, or if the dry run fails, readiness becomes `BLOCKED` before the operational readiness query is executed.

The dry-run result is a per-execution estimate, not a monthly usage meter. The operator must still review actual BigQuery usage and Cloud Billing before enabling a recurring refresh.

## Looker Studio

The user-owned Looker Studio report may connect to the curated BigQuery views. BigQuery usage generated by that report counts toward the same Google Cloud usage limits, so report refreshes and exploratory queries should remain modest while the project is operated as a no-mandatory-cost portfolio.

## Production gate

A recurring refresh must not be enabled until all of these are true:

1. Workload Identity Federation smoke test is green.
2. Reviewed mappings are populated and production ingestion is green.
3. BigQuery storage passes the automated 8 GiB safety gate and current monthly query usage is comfortably inside the free tier.
4. All three website snapshot queries pass the automated 250 MB-per-query dry-run gate.
5. The operator has reviewed current Google Cloud pricing, usage, and billing configuration.
